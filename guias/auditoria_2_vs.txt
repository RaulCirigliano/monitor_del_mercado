## Contexto del proyecto

Es una aplicación Python llamada “Monitor del Mercado”. Recopila noticias RSS, obtiene cotizaciones con yfinance, analiza información con Ollama o, opcionalmente, Google Gemini, genera reportes Markdown y ofrece un dashboard web. Incluye un lanzador para Windows (`lanzar-bot.bat`) y otro para Linux (`launch.sh`). El dashboard también contempla una integración opcional con una aplicación externa de trading en el puerto 18767.

El objetivo normal del sistema es investigar y mostrar información: no debe realizar operaciones financieras reales ni enviar instrucciones a brokers.

1. Hallazgos principales
Alto — Auto-inyección habilitada de forma predeterminada. El dashboard podía reenviar automáticamente una tesis al servicio local de Trading Ollama tras cada escaneo; la casilla aparecía marcada al abrirlo. Aunque no era una conexión directa a un broker, podía alimentar un sistema externo de trading sin una activación explícita en esa sesión.
Alto — Fallo de IA presentado como análisis concluido. Si Ollama no respondía, el evaluador contaba noticias sin clasificar como “ruido” y generaba una conclusión que podía sugerir que no había oportunidades.
Medio — Datos y guías inventados al leer reportes incompletos. El parser completaba campos ausentes con puntuaciones, ratios y tesis predeterminados; además, el dashboard podía fabricar una guía operativa para reportes que no la incluían.
Medio — Datos de mercado potencialmente engañosos. Si faltaban extremos anuales en yfinance, se sustituían por máximos y mínimos de cierres, y valores no finitos podían llegar al modelo.
Medio — Estado de Ollama incompleto y respuesta inválida mal manejada. Un proceso activo se mostraba como disponible aunque faltara el modelo configurado; una respuesta HTTP con JSON inválido podía terminar en un error secundario por una variable no inicializada.
Medio — Operatividad e instalación. El lanzador Linux dependía de una ruta absoluta de esta computadora, faltaba el lanzador Windows mencionado en la documentación y Gemini, opcional, se instalaba como dependencia obligatoria.
Medio — Fallos de feeds silenciosos y posible sobrescritura. Errores de descarga RSS podían parecer una ingesta vacía normal; reportes creados en el mismo segundo podían compartir nombre.
Medio — Horario de futuros incompleto. La comprobación no respetaba la apertura dominical ni el cierre semanal que declaraba su propia configuración.
No confirmé hallazgos críticos. También revisé las restricciones locales de la API y el rechazo de rutas de reportes fuera del directorio permitido.
